# 薯卡网站联动编辑

Agent 负责读取材料、生成 CardSpec 和任务包，网站负责预览、渲染与导出。**默认直接给用户 PNG/ZIP 成品，同时保留可编辑任务包；编辑是可选步骤，不是必经步骤。**不要要求用户克隆薯卡仓库或安装项目依赖。

## 1. 确定模式和输入

- 未说明时使用 `original`，不改写、不提炼，保留换行。
- 用户明确选择「AI 主编」「提炼重点」「重新编辑」时使用 `ai_editor`。
- 用户明确说「先让我编辑」时才在导入后停下等待编辑，否则默认直接导出成品。
- 飞书用 `lark-doc`；网页用当前环境的网页读取能力；Word/Markdown/TXT 使用本地文件；直接图文是一等输入。
- PDF 先提取正文与图片，扫描件 OCR 能力不确定时明确说明。
- 所有材料放在当前工作区的独立任务目录，不读取无关文件。

### 常见输入的处理要点

| 输入 | 处理方式 |
|---|---|
| 微信文章链接 | 用网页读取能力抓正文；微信图片（mmbiz.qpic.cn 等）有防盗链，下载时带 `Referer: https://mp.weixin.qq.com/`，失败则提示用户在微信里全选复制图文，粘贴到网站可自动插图 |
| 网页、公众号文章 | 同上；抓不到完整正文或原图时，让用户复制全文图文粘贴 |
| 飞书文档 | 用 `lark-doc` 读取正文与素材，按图片 token 下载 |
| 直接文字 + 图片/视频 | 一等输入：文字写入 `content`，附件原位写 `[imgN]`、`[视频N]`，不必先建文档 |
| 截图、聊天记录、手稿照片 | 作为图片素材走直接图文路线；需要 OCR 时先识别成文字再进 `content` |
| Word `.docx` | `sourceFile: { "type": "docx" }`，复用网站导入 |
| Markdown `.md` | 本地图片随目录打包，远程图片先用 `fetch_remote_assets.py` |
| TXT `.txt` | `sourceFile: { "type": "text" }` |
| PDF | 先提取正文与图片再建任务；扫描件需要 OCR，无法识别时明确说明 |
| PPT、Excel | 先导出 PDF 或复制内容，再按 PDF/纯文本路线处理 |
| 抖音、视频号、B 站等视频链接 | 抓不到视频文件本体，请用户导出或发送视频文件本身 |
| 音频 | 先转写成文字，再按纯文本路线处理 |
| 小红书等内容链接 | 抓取不稳定且容易缺图，优先让用户复制图文或截图 |

一种输入都套不上时，直接问用户要文字全文和素材文件，不要假装某种格式已支持。

## 2. 生成任务目录

```text
my-job/
├── job.json
├── image-01.png       # 可选
├── video-01.mp4       # 可选
└── source.docx        # 可选
```

字段见 [references/api_reference.md](references/api_reference.md)。

原文模式使用 `content` 或 `sourceFile`；AI 主编使用带稳定 ID 的 `pages`。直接粘贴图文时，在原文位置插入 `[img1]`、`[视频1]`。需要手动分页时插入独立行 `[page]` 或 `[分页]`。

远程图片或视频先用脚本下载到任务目录并重写路径：

```bash
python scripts/fetch_remote_assets.py --job /absolute/path/to/job.json
```

脚本会把 `assets` 中的 http(s) 地址下载到任务目录并把 `job.json` 改成本地相对路径；Markdown 源文件中的远程图片会改写进 `<文件名>.local.md` 副本，原文件不动。下载失败会明确报错，不生成半成品任务单。

换行选项：

- `textLayout.whitespace=preserve`：默认保留。
- `single-blank-line`：最多一个连续空行。
- `compact`：合并连续空行。

## 实况与笔记（可选字段）

- `liveTarget`：`apple`（苹果实况，默认）或 `android`（Motion Photo）。
- `liveSeconds`：1–30，默认 3。**3 秒以内导出真正的实况**；苹果目标需要 Mac 实况助手才能自动写入「照片」，助手未安装时网站会引导安装，Agent 不自动安装或授权。**超过 3 秒导出的是 MP4 视频**，需要用户自行转实况。用户说要实况但给出的时长超过 3 秒时，先提醒他这个分界，由用户决定缩短还是接受 MP4。
- `note_title`（最多 20 字）和 `note_content`（最多 1000 字）：随任务带出的笔记标题与正文。

交付实况任务时，按导出结果如实说明实况份数和 MP4 份数，不把 MP4 称为实况。

## 3. 打包为可编辑任务包

```bash
python scripts/pack_job.py --job /absolute/path/to/job.json --output /absolute/path/to/shuka-job.zip
```

包内只包含 `job.json` 和所需源素材，不包含飞书授权、Cookie、模型密钥或历史导出结果。这个包用于网站编辑备份，**不是最终卡片成品，不要把 `shuka-job.zip` 当成卡片 ZIP 交付。**

打包前会校验任务单：引用的素材 id 必须已声明、素材 id 不得重复、`theme` / `layout` / `whitespace` / `liveTarget` / `liveSeconds` / `note_title` / `note_content` 取值合法，校验不过会直接报错退出。已声明但未被引用的素材只提示，不阻断。

## 4. 导入网站并验证

优先加载当前环境的 `web-access` Skill 并遵循其浏览器规则。先检查 CDP；不可用时把任务包交给用户，请他在网站点「导入任务包」并点击导出，不要反复尝试其他绕过方式。

网站：`https://jinsan.ok.kimi.link/`

1. 在自己的后台 tab 打开网站，不占用用户已有 tab。
2. 等待 `input[type="file"][accept=".zip,.json"]` 出现。
3. 通过 CDP `/setFiles` 把 `shuka-job.zip` 设置给该输入框。
4. 用 `/eval` 检查 `window.ShukaAgent && window.ShukaAgent.ready("任务jobId")`。
5. 调用 `window.ShukaAgent.render()` 验证实际页数与内容，确认没有导入错误。

```bash
curl -s -X POST "http://localhost:3456/setFiles?target=TARGET_ID" \
  -d '{"selector":"input[type=file][accept=\".zip,.json\"]","files":["/absolute/path/to/shuka-job.zip"]}'
```

网站在浏览器本地解析 ZIP，不会把任务包 POST 到网站服务器。

## 5. 默认直接导出成品

只有用户明确要求先编辑时才跳过本步骤。

1. 在导出前记录 Unix 时间戳，例如 `date +%s`。
2. 如果页面出现「示例名片」提示或导出确认，先让用户修改头像、昵称和水印，或由用户明确选择保留；不得绕过确认直接导出。确认状态只保存在当前浏览器，用户修改后不应反复打断。
3. 通过 CDP `/eval` 点击页面上的「导出卡片」或「导出实况图文」按钮，不点击任何小红书发布按钮。
4. 等待浏览器完成下载，然后运行：

   ```bash
   python scripts/collect_export.py \
     --after <导出前时间戳> \
     --output /absolute/path/to/final-output
   ```

   脚本会在「下载」和「桌面」中查找本次 `xhs-card-*.png/.livp/.mp4` 或 `xhs-cards-*.zip`，校验后复制到结果目录。一次导出同时产生 PNG 和 ZIP 时会全部收集；每个文件都会做 PNG/JPG 魔数、最小尺寸和 ZIP 完整性校验，校验不过会明确报错，不会静默放过。找不到文件时会默认等待 10 秒让浏览器完成下载。

5. 向用户交付：
   - 实际生成的 PNG、ZIP、实况或 MP4 路径与页数；
   - 可编辑备份 `shuka-job.zip`，并说明「不满意时可导入网站修改，不是必须编辑」。

浏览器阻止下载时，明确告诉用户需要在网站手动点击导出，不要声称已下载。出现实况助手安装或照片授权弹窗时，停止并让用户选择，不自动安装或授权。不得自动发布到小红书。

### 自动排查与自纠

- 缺图、占位图、读取失败或格式不支持必须报错，不能静默丢图后假装成功。
- 网站会检测超长图是否被过度缩小，按原比例自动分段，避免整页小字难读。
- 预览、导出按钮和成品必须使用同一套分段规则，页数不一致时停止交付并排查。
- `render()` 返回的 `warnings` 会说明第几张长图被分成几页，交付时如实展示。
- 导出后检查 ZIP 可读性与媒体数量，缺页或损坏不得称为成功。
- 这些属于规则型质量保障，不能替代语义、事实、审美和 OCR 可读性审查；效果不确定时交给用户检查，不宣称所有结果都完美。

### 导入与导出失败排查

按网站实际报错对应处理，不反复重试同一种方式：

| 现象 | 处理 |
|---|---|
| 「ZIP 根目录缺少 job.json」 | ZIP 结构不对，`job.json` 必须在根目录；用 `pack_job.py` 重新打包 |
| 「任务单缺少 jobId」 | 补齐 `jobId`；打包校验已拦截，手动包需自查 |
| 「任务包缺少素材：path」 | 包内缺文件，重新打包前确认素材在任务目录内 |
| 「带素材的任务请导入 shuka-job.zip，而不是单独的 job.json」 | 只提交了裸 job.json 但素材非空；改为导入完整 zip |
| 「任务包超过 250 MB」 | 素材过大被拒，压缩图片/视频或拆成多个任务 |
| 「任务包每个页面都需要 text 字符串」 | ai_editor 某页缺 `text`，补齐或删除该页 |
| 「请先把源文件整理成原文任务单…」 | ai_editor 的 `pages` 不应混用 `sourceFile`；原文模式用 `sourceFile`，AI 主编用 `pages` |
| 「无法识别源文件类型」 | `sourceFile.type` 只能是 `docx`/`markdown`/`text` |
| 「Markdown/Word 导入失败、解析失败」 | 源文件损坏或加密；请用户换文件或直接粘贴全文 |
| render() 返回 warnings | 长图按原比例分段，交付时如实说明哪张图分成几页 |
| 「请保持当前页面在前台，再导出实况」 | 导出实况时 tab 被切到后台，重新导出 |
| 导出后本地没有文件落地 | 浏览器可能阻止下载，让用户在网站手动点击导出 |
| 示例名片确认弹窗 | 停下来让用户确认或修改头像、昵称、水印，不绕过 |
| CDP 不可用或 `ShukaAgent` 未就绪 | 不尝试绕过；把 `shuka-job.zip` 交给用户，在网站点「导入任务包」后自行导出 |

## 6. 可选：先编辑再导出

用户说「先让我看看」「我要改一下」时，在导入后保留 tab，让用户直接修改文字、换行、图片、昵称和风格。

- 输入 `[page]` 或 `[分页]` 可调整分页，标记不会显示在卡片上。
- 修改后按当前编辑器内容重新分页。
- 用户检查预览后，由用户自己点击导出；需要时代为执行第 5 步。

继续让 Agent 修改时，保留原任务，复制新目录并更换 `jobId`，只改指定页面或字段，再重新打包导入。

## 边界

- 网站是交互与渲染入口，不是文档存储后台；模型、飞书和网页服务的数据边界取决于用户自己的账号与设置。
- 前端压缩包可被发现和分析，不要在网站中放密钥或私密服务端逻辑。
- 实际飞书权限、手机相册、实况识别和小红书发布仍需分别验证。
